## 1. 프로젝트 핵심

배터리의 초기 충·방전 데이터를 이용해 전체 수명 또는 장·단수명 여부를 예측한다. EDA에서 발견한 특성을 피처 설계와 모델 선정에 연결하고, 다른 실험 배치에서도 예측이 유효한지 평가하는 데이터 사이언스 프로젝트다.

- 도메인: ESS 및 배터리 상태·수명 관리
- 데이터: MIT–Stanford Battery Dataset, Severson et al. (2019)
- 선택 과제: **회귀 또는 분류 중 하나**
- 필수 학습·평가: Batch 1 학습, Batch 2 테스트
- 추가 평가: Batch 3 테스트는 선택 사항
- 핵심 산출물: DAY 1 설계 PDF, DAY 2 공개 GitHub 저장소와 README

## 2. 도메인 주요 내용

### 2.1 ESS와 구성 요소

ESS(Energy Storage System)는 다른 곳에서 생산한 에너지를 저장한 뒤 필요한 시점에 공급하는 시스템이다. 배터리를 이용하는 ESS를 BESS라고 한다.

주요 용도는 재생에너지 출력 변동 완화, 피크 부하 감소, 비상 전원 및 데이터센터 UPS, 전력 공급 안정화다.

| 구성 요소 | 역할 |
| --- | --- |
| 배터리 | 전기 에너지를 화학 에너지로 저장하고 방전 시 공급 |
| BMS | 전압·온도·상태 감시, 셀 밸런싱, 과충전·과방전 등 보호 |
| PCS | 배터리의 DC와 전력망의 AC 사이 전력 변환 |
| EMS | 충·방전 스케줄과 운영 최적화, 가격·수요·안전 조건 반영 |

배터리는 셀, 모듈, 팩·랙, 컨테이너 등의 계층으로 구성된다. 이번 데이터는 실험용 **셀 단위** 데이터이므로, 셀 예측 결과를 ESS 전체 수명으로 곧바로 해석하면 안 된다.

### 2.2 배터리 열화

리튬이온 배터리는 양극, 음극, 분리막, 전해질로 구성된다. 충전 시 리튬이온은 양극에서 음극으로, 방전 시 반대로 이동한다.

반복 사용 중 리튬 손실, SEI 성장, 내부 저항 증가, 전극 구조 변화 등이 발생한다. 용량 감소와 출력 저하가 나타나며, 충전 조건·온도·사용 방식이 열화에 영향을 줄 수 있다.

### 2.3 상태 지표와 예측 타깃

| 지표 | 의미 | 프로젝트에서의 구분 |
| --- | --- | --- |
| SOC | 현재 가용 용량 대비 충전 잔량 비율 | 현재 충전 상태 |
| SOH | 초기 대비 현재 용량 등의 건강 상태 | 본 과제는 용량 기준 80%를 수명 종료 기준으로 사용 |
| SOP | 현재 조건에서 가능한 최대 출력 | 수명과는 별도 지표 |
| Cycle Life | 수명 종료 기준에 도달하기까지의 총 사이클 수 | 회귀 타깃 `cycle_life` |
| RUL | 현재 시점부터 수명 종료까지 남은 수명 | 총수명과 다름; 단순 사이클 기준으로는 총수명에서 현재 사이클을 뺀 값 |

초기 수명 예측은 셀 선별, 교체 계획, 유지보수 우선순위 결정에 활용할 수 있다. 다만 실험실 데이터의 성능만으로 현장 비용 절감이나 배포 효과를 입증할 수는 없다.

## 3. 데이터와 예측 과제

### 3.1 데이터 배치

| 파일 식별명 | 배치 | 자료상 크기 | 사용 범위 |
| --- | --- | --- | --- |
| `2017-05-12` | Batch 1 | 약 2.8 GB | EDA, 모델 학습 및 내부 검증 |
| `2018-02-20` | Batch 2 | 약 1.9 GB | EDA, 필수 최종 테스트 |
| `2018-04-12` | Batch 3 | 약 3.0 GB | EDA 필수, 모델 추가 테스트 선택 |
| `2018-04-03 varcharge` | Extra | 약 0.1 GB | 별도 충전 최적화 연구 데이터; 기본 과제 대상 아님 |

원논문 소개 자료는 고속 충전 조건의 LFP/흑연 셀 124개를 설명한다. 실제 사용 셀 수는 파일 구조와 제외 기준을 확인한 뒤 별도로 기록해야 한다.

### 3.2 주요 데이터 필드

| 범위 | 필드 | 용도 |
| --- | --- | --- |
| 셀 | `cycle_life`, 충전 프로토콜 | 타깃, 실험 조건 |
| 사이클 요약 | `QDischarge`, `QCharge` | 방전·충전 용량과 초기 변화 |
| 사이클 요약 | `IR`, `Tmax`, `Tavg`, `Tmin`, `chargetime` | 저항·온도·충전 시간 특성 |
| 사이클 상세 | `t`, `V`, `I`, `T`, `Qc`, `Qd` | 시간에 따른 전압·전류·온도·용량 |
| 보간 곡선 | `Qdlin` | 전압 축으로 보간된 방전 용량; ΔQ(V) 계산 |
| 보간 곡선 | `Tdlin`, `discharge_dQdV` | 온도 곡선, 방전 용량의 전압 미분 특성 |

자료상 `Qdlin`은 2–3.6 V 구간의 1,000개 포인트다. 실제 파일의 배열 길이와 전압 정렬을 확인하고 사용한다. 예제 노트북은 용량 필드를 `QD`, `QC`로 바꾸므로 원본과의 매핑도 기록한다.

### 3.3 회귀와 분류 중 선택

| 구분 | 회귀 | 분류 |
| --- | --- | --- |
| 입력 범위 | 초기 100사이클 | 초기 5사이클 |
| 타깃 | 전체 `cycle_life` | 장수명·단수명 라벨 |
| 예시 정의 | 총 사이클 수 | `cycle_life >= 550`이면 1, 아니면 0 |
| 과제 평가 지표 | MAPE (%) | F1-Score, Accuracy |
| 자료의 비교 목표 | MAPE 9.1% | 오류율 4.9%, 즉 Accuracy 95.1% |

분류 임계값 550은 자료의 예시다. 팀이 사용할 기준과 이유, 클래스 비율을 명시한다. 논문과 비교할 때 입력 기간, 라벨 기준, 데이터 제외 조건, 지표 정의가 같은지도 확인해야 한다.

## 4. 필수 요구사항

### 4.1 DAY 1: EDA와 모델 전략

**Batch 1·2·3 모두에 대해 다음 5개 질문을 분석하고 배치 간 차이를 비교한다.**

1. **Cycle Life 분포**: 히스토그램, 장수명(>1,000)·단수명(<500) 비율, 유독 짧은 수명의 셀과 원인 가설
2. **열화 곡선**: 사이클별 방전 용량 변화, 열화 속도의 일정성·가속성, 급격한 열화 시작점(knee point)
3. **ΔQ(V) 곡선**: `Q100(V) - Q10(V)` 계산, 장·단수명 셀 비교, 구분에 유용한 통계 피처 추출
4. **충전 조건과 수명**: C-rate·프로토콜별 평균 수명, 전류 패턴과 열화의 관계
5. **초기 신호와 수명의 관계**: 초기 피처의 상관관계, 주요 신호, 피처 간 다중공선성

분석 결과를 바탕으로 다음 전략을 제시한다.

- 회귀 또는 분류 선택 및 타깃 정의
- EDA에 근거한 피처 선정·생성
- 결측치·이상치·스케일 등 데이터 처리 전략
- 후보 모델과 선정 이유
- 학습·검증 분할과 평가 방법

그래프만 나열하면 안 된다. 각 분석에 **그래프, 해석, 시사점, 모델 전략 반영**이 있어야 한다.

### 4.3 성능 보고 형식

| 보고 항목 | 데이터·의미 |
| --- | --- |
| Train (Batch 1 CV) | 교차 검증 평균; 학습 데이터에 다시 예측한 점수가 아님 |
| Valid (Batch 1 Hold-out) | Batch 1의 별도 검증 셀 성능 |
| Test (Batch 2) | 필수 최종 테스트 성능 |
| Gap (Train-Valid) | 내부 평가 간 차이와 과적합 가능성 |
| Gap (Valid-Test) | 배치 간 일반화 차이 |
| Gap (Target-Test) | 과제 목표 대비 차이 |
| Test (Batch 3), Gap (Batch2-Batch3) | 추가 평가를 수행한 경우 보고 |

회귀는 MAPE (%), 분류는 F1-Score와 Accuracy를 같은 행 구성으로 작성한다. 목표 F1 값은 자료에 없으므로 임의로 만들지 않는다.

**Gap 계산식은 반드시 명시한다.** 원자료의 회귀 표는 항목명과 양수 해석이 일관되지 않는다. 아래는 양수일 때 성능 저하·목표 미달을 나타내는 권장 계산식이며, 제출 표에는 요구된 항목명을 유지한다.

| 제출 항목명 | MAPE: 낮을수록 좋음 | Accuracy·F1: 높을수록 좋음 |
| --- | --- | --- |
| Gap (Train-Valid) | Valid − Train | Train − Valid |
| Gap (Valid-Test) | Test − Valid | Valid − Test |
| Gap (Target-Test) | Test − Target | Target − Test |
| Gap (Batch2-Batch3) | Batch 3 − Batch 2 | Batch 2 − Batch 3 |

퍼센트 지표의 단순 차이는 퍼센트포인트(%p)로 표기한다. F1은 양성 클래스와 averaging 방식을 명시하고, 모든 분할에서 동일한 정의를 사용한다.

## 6. 구현·해석 시 참고사항

### 6.1 데이터 누수 방지

- 학습·검증은 **셀 단위**로 분리한다. 동일 셀의 사이클 행을 양쪽에 나누면 안 된다.
- 스케일링, 결측치 대체, 피처 선택은 각 학습 분할에서만 학습한다.
- 초기 100사이클 또는 5사이클 이후 정보는 모델 입력에 사용하지 않는다. 전체 열화 곡선과 knee point는 설명용 EDA와 예측용 피처를 구분한다.
- 첫 5사이클 분류 모델에 `Q100 - Q10` 피처를 넣을 수 없다. 분류 입력 기간 안에서 별도 피처를 설계한다.
- Batch 2 테스트 결과로 반복 튜닝하면 최종 평가의 독립성이 약해진다.
- 과제상 Batch 2·3 EDA는 필수지만, 테스트 라벨을 이용한 모델 선택·최적화와 혼동하지 않는다. 테스트 평가 전에 전략과 모델을 확정하고 분석 범위를 기록한다.

Hold-out을 사용한다고 충전 프로토콜 중복이 자동으로 사라지는 것은 아니다. 미관측 프로토콜 일반화를 평가하려면 프로토콜 기준 그룹 분리가 필요하다. CV도 그룹 기준으로 구성할 수 있다. 별도 Hold-out 셀은 CV·튜닝 학습에 섞지 않는 구성을 권장한다.

### 6.2 배치 차이와 이상치

- Batch 3는 수명 분포와 충전 곡선 시작 시점이 다를 수 있다.
- 사이클 번호, 결측 사이클, 배열 길이, 전압 정렬을 확인한다.
- `Qdlin` 단순 차감 전에 비교 가능한 조건인지 점검한다.
- 일부 셀은 수집 공백이나 데이터 품질 문제가 있을 수 있다. 제외한 셀 ID, 기준, 개수를 기록한다.
- 용량이 낮다고 무조건 이상치로 제거하면 실제 말기 열화를 지울 수 있다. 시각화 정제와 모델 학습 전처리를 구분한다.
- 상관관계만으로 충전 조건이 수명 감소의 원인이라고 단정하지 않는다.

### 6.3 원논문·사업 효과와 비교

- 과제 안내는 회귀 목표를 MAPE 9.1%로 지정한다. 첨부 초록의 표현은 시험 오차 9.1%이므로, 논문과 엄밀히 비교하려면 원문의 지표 정의를 추가 확인한다.
- 목표 수치에 도달해도 입력 기간·분할·라벨·제외 조건이 다르면 논문 재현을 주장할 수 없다.
- 데이터는 고속 충전 실험 셀이다. 실제 ESS의 온도, 운전 패턴, 셀 불균형, 화학 조성 변화에 대한 추가 검증이 필요하다.
- 도메인 자료의 시장 성장률·비용 절감 수치는 배경 설명이다. 이 프로젝트의 실증 결과로 제시하지 않는다.

### 6.4 첨부 자료를 활용하는 방법

배달 매출 예측 스크린샷은 **EDA에서 모델 전략을 도출하는 설명 방식**의 예시다. 해당 예시의 LightGBM이나 목적함수를 배터리 과제의 필수 모델로 받아들이면 안 된다.

보고서는 발견한 데이터 특성, 도메인 가설, 피처·전처리 선택, 후보 모델·검증 방법을 논리적으로 연결한다. 배터리 구조와 충·방전 이미지는 개념 설명에 활용하되, 첨부 ESS 구성 그림은 하이브리드 시스템 예시이므로 일반적인 BESS 구성과 구분한다.

## 7. 예제 노트북의 현재 범위

`30-ESSHealth-scratch.ipynb`는 시작용 참고 코드이며, 과제를 완성한 파이프라인은 아니다.

- `.mat` 파일 로딩과 셀·사이클 구조 정규화
- Batch 1 요약 데이터 추출
- 수명 분포, 용량 곡선, 충전 프로토콜, 상관관계 등의 기본 EDA
- 아직 필요한 작업: Batch 2·3 비교 EDA, ΔQ 피처 구현, 타깃 확정, 모델 학습·검증 및 성능 보고

사용 전 확인할 사항:

1. 데이터 경로가 작성자의 로컬 경로로 고정돼 있으므로 변경한다.
2. MATLAB v7.3 파일은 HDF5 형식이다. 예제는 `mat73` 로딩을 먼저 시도하고 실패하면 `scipy.io.loadmat`을 시도한다. 설명문의 순서와 코드가 다르므로 실제 코드를 기준으로 확인한다.
3. 일부 그래프는 셀 순서로 색을 배정한다. 색을 장·단수명으로 설명하려면 실제 수명에 맞춰 색을 지정해야 한다.
4. 일부 EOL 선은 `0.88 × nominal capacity`로 설정돼 있다. 80% 기준과 맞지 않으며, 셀별 초기 용량을 기준으로 정의할지도 확인해야 한다.
5. 노트북의 통계·해석은 저장된 예시다. 정제 후 사용 데이터로 다시 계산하고, 인과관계 주장과 추측은 관측 결과와 구분한다.
